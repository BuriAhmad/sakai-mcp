# Evidence and workspace handling

Resolve authoritative IDs and agree the grading plan before bulk retrieval. Listing/detail tools return metadata and ResourceLinks. Read them through resources/read or read_assignment_grading_resource using the existing authenticated MCP connection. No second MCP client, token handling or browser-cookie download is needed.

For capture, select explicit submission IDs/content revisions with export_assignment_submissions and inspect get_assignment_submission_export. Check per-row status, original byte hashes, sizes, identity mappings and expiry. Current exports can be partial: assess only complete, unchanged selected evidence; do not infer a complete class roster or score unavailable work. Attachments remain unsupported by the current migrated adapter. Inline HTML is evidence, not an MCQ TXT attachment or extracted plain text.

If the chosen method needs local files, use a private run folder inside the workspace selected by the user. ResourceLinks and EmbeddedResource responses do not prove that files were saved. Use the host's byte-preserving file capability, verify the resulting size/SHA-256 against resource metadata, and retain original bytes separately from extracted text, checking scripts and results. Decode SDK blobs as base64 and encode SDK text as UTF-8 without newline/BOM normalization. Do not reconstruct binary evidence from model summaries. If faithful file delivery is unavailable, choose an appropriate supported method or report that gap; do not start another authenticated importer. The actual host-to-file path still needs acceptance in the intended CLI client.

A local script can implement explicit exact rules or tests for this assignment; it is one option alongside direct checks, rubric-guided AI assessment and human review. Preserve the script/configuration hash, input hashes, authoritative ID mapping and per-criterion evidence. Test known correct, incorrect and malformed examples. Scripts that process evidence are distinct from executing student code, which requires an approved isolated runner. Do not invent marking rules to fill missing policies.

Keep proposals and review exceptions in the authorized workspace/host workflow. Old get_assignment_grading_proposal and report resources are compatibility readers for preserved records, not a required route for new assessment. No new server MCQ proposals are generated; existing records are neither deleted nor migrated automatically. Existing expiry and authorization checks remain.

For official writes, prepare_assignment_grade_payload hashes and validates explicit rows without deciding their marks. Present its exact commit_arguments for approval, then use save_assignment_grades or the separately approved release_assignment_grades. Changing evidence or payload invalidates approval; uncertain outcomes require receipt reconciliation plus authoritative readback, never blind retry.
