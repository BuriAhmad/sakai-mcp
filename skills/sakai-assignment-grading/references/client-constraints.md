# Capability constraints

The fourteen grading tools and resources require independent disabled-by-default `ASSIGNMENT_GRADING_ENABLED` and `mcp.assignment.grading.enabled` gates. Development implementation is not deployment or acceptance. Preserve the five V1 tools and three independent assignment-setup tools. Discover prepare_assignment_mcq_grades, prepare_assignment_grade_payload and the resource reader before using this migrated workflow. If they are absent, report that service 0.2.0 deployment is required; do not fall back to the removed importer. Do not change runtime flags or start compute to use this Skill.

Initial official writes support current submitted individual, site-wide point assignments with no Gradebook link or one verified Assignment-owned external item. Anonymous/group grading, group Gradebooks, numeric/internal links, rubric/peer/external submission integrations and historical attempts are unsupported. Read completeness and capabilities; scoped counts are not course totals. A missing hash/resource or permission is not an empty submission.

Content export and private proposals require the existing explicitly provisioned persistent Sakai directory (mcp.assignment.grading.storage). Reads are actor/course/assignment bound and reauthorize access; exports/proposals expire after 24 hours. Use tools and resources through the host's normal authenticated MCP connection. No importer OAuth client or external script exists. Text resources preserve UTF-8 bytes; binary resources use SDK blobs and may exceed a particular host's response budget. ResourceLinks do not prove local-file materialization. The server deterministic evaluator needs no host filesystem; a tools-only host can use proposal pages and read_assignment_grading_resource.

Save/release callbacks lock Assignment and submission rows and use native submission versioning. A persistent operation journal records each attempted row before native mutation. Crashes or projection failures preserve unknown/partial stages; replay returns the receipt and does not automatically repair them. Exactly-once notification delivery is not claimed. Manual repair requires a reviewed academic action; do not use another operation ID to evade a conflict.

Design and acceptance evidence live in `docs/SAKAI_ASSIGNMENT_GRADING.md` and `docs/evidence/mcp/assignment-grading-local.md` in the repository. Native TA role/section/item permissions, Student UI parity, persistent storage lock semantics and intended host approval/download behavior require later authorized live acceptance.
