# MCP service

This directory contains the project-owned MCP service package under `src/sakai_mcp/`. Its implementation and tests are being added in runbook order. Follow the scoped [`AGENTS.md`](AGENTS.md) for security and layout rules.

Dependencies are pinned in [`pyproject.toml`](pyproject.toml) and [`uv.lock`](uv.lock). For local development, run `uv sync --locked` here. The selected SDK is MCP Python 2.2.0. `config.py` validates non-secret HTTPS URLs, Entra audiences and scopes, and request limits. `auth.py` verifies the inbound MCP delegated token using configured Entra JWKS, issuer, tenant, audience, time claims, scope, and `tid + oid`; it implements the pinned SDK's `TokenVerifier` shape. `obo.py` uses certificate-backed MSAL OBO and independently validates the distinct Sakai API token, including its singleton institutional ID claim. `sakai_client.py` exposes the five narrow Sakai routes through a fixed-origin, bounded HTTP client. Credential files must be mounted or supplied outside Git. Run `uv run --no-sync pytest -q` for focused tests. The MCP server is still under implementation, so the service is not runnable yet.

Do not place upstream Sakai source here. The implementation plan, architecture constraints, phase gates, and acceptance criteria are in [`docs/MCP_IMPLEMENTATION_RUNBOOK.md`](../../docs/MCP_IMPLEMENTATION_RUNBOOK.md). Consult and update that runbook as implementation decisions are verified or the plan changes.
