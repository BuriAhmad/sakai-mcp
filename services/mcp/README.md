# MCP service

This directory contains the project-owned MCP service package under `src/sakai_mcp/`. Its implementation and tests are being added in runbook order. Follow the scoped [`AGENTS.md`](AGENTS.md) for security and layout rules.

Dependencies are pinned in [`pyproject.toml`](pyproject.toml) and [`uv.lock`](uv.lock). For local development, run `uv sync --locked` here. The selected SDK is MCP Python 2.2.0. `config.py` validates non-secret HTTPS URLs, Entra audiences and scopes, and request limits. `auth.py` verifies inbound delegated tokens; `obo.py` performs certificate-backed MSAL OBO and independently validates the Sakai API token; `sakai_client.py` uses only the five fixed-origin Sakai routes. `server.py` exposes exactly five tools through authenticated, stateless Streamable HTTP at `/mcp`. The catalog is static; Sakai checks site permissions on every call, including manual invocations of instructor tools. Run `uv run --no-sync pytest -q` for the local test suite. The service passed local protocol and end-to-end development checks, but has not been deployed to Azure.

Set `MCP_PUBLIC_URL`, `SAKAI_BASE_URL`, `ENTRA_TENANT_ID`, `MCP_RESOURCE_CLIENT_ID`, `MCP_ISSUER`, `MCP_AUDIENCE`, `MCP_JWKS_URI`, `SAKAI_RESOURCE_CLIENT_ID`, and `SAKAI_AUDIENCE` from verified environment metadata. Set `OBO_PRIVATE_KEY_FILE` and `OBO_CERTIFICATE_FILE` to runtime-mounted files outside Git. Defaults include delegated scopes `mcp.access` and `sakai.mcp.access`; `config.py` lists bounded timeout/page-size options. With these settings present, start locally from this directory using `uv run --no-sync uvicorn sakai_mcp.asgi:create_app --factory --host 127.0.0.1 --port 8000`. The actual development ingress and Key Vault credential mount are later deployment work.

The process exposes unauthenticated `GET /live` and `GET /ready`, each returning HTTP 200 after local app construction. They never call Entra or Sakai. The authenticated `/mcp` route and protected-resource metadata are separate. Tool audit output contains generated request IDs and hashed identity/course/object references with stable outcomes and latency; it excludes tokens, content, and raw LMS IDs. Container Apps sends stdout to the planned Azure log sink. Tests under `tests/unit/`, `tests/integration/`, `tests/protocol/`, and `tests/security/` run in the existing repository CI without live credentials.

The `Dockerfile` installs production dependencies from `uv.lock` into a non-editable environment, strips build tooling from the final pinned Python 3.11 image, and runs as UID/GID 10001 on port 8000. `.dockerignore` excludes local environments and credential files. From the repository root, `scripts/build-mcp-image.sh services/mcp sakai-mcp:local FULL_COMMIT_SHA` builds and performs pinned Trivy source/dependency, secret, and image scans. The CI image job runs this path on every push and PR; the manual MCP workflow can build an exact commit on `main` without deploying. See [the MCP release guide](../../docs/MCP_RELEASES.md) for its `check-only`/`deploy` modes, digest identity, Azure prerequisites, and rollback. Cloud deployment remains Phase 18.

Do not place upstream Sakai source here. The implementation plan, architecture constraints, phase gates, and acceptance criteria are in [`docs/MCP_IMPLEMENTATION_RUNBOOK.md`](../../docs/MCP_IMPLEMENTATION_RUNBOOK.md). Consult and update that runbook as implementation decisions are verified or the plan changes.
