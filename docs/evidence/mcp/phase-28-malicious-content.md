# Phase 28 — malicious LMS content (2026-09-28)

Status: **PASS for the representative server-side gate**. External model/host interpretation remains untested and is not a server guarantee. Phase 25 remains IN PROGRESS.

The new synthetic composed-adapter test `services/mcp/tests/integration/test_untrusted_content.py` returned announcement title/body and submission metadata containing fake system instructions, requests for another student's grades and a bearer token, a hidden-tool/acting-user command, a misleading URL/shell command, and forged tool-call JSON. The content was returned unchanged as ordinary data. The test then manually requested a foreign course's announcements and submissions, an unauthorized create, and a nonexistent course. The simulated Sakai permission boundary returned `FORBIDDEN` for all three unauthorized operations and `NOT_FOUND` for the nonexistent course. Only one POST was attempted, and it was denied. The adapter retained its fixed Sakai origin and OBO-provided downstream bearer; payload text supplied neither authority nor a destination.

Source inspection confirms the V1 server registers exactly the five fixed tools in `server.py`; tool parameters contain no acting user, token, or URL. `sakai_client.py` constructs only fixed routes, and the Sakai narrow controllers perform site and assignment permission checks under the validated delegated user context. Submission **body** and assignment prose are not in the V1 read response; the tested submission surface is metadata. Existing deployed Phase 21–23 evidence covers token separation, cross-course denials, and manual hidden/privileged tool calls. Phase 27 covers concurrent identity cleanup. These results are cited as existing deployed evidence, not newly run live injection probes.

Verification: `uv run --no-sync pytest -q` passed **42/42**; Ruff and mypy passed. No credential, student payload, or secret was used or stored. No keyword filter or runtime security change was added. A model host can still misunderstand untrusted text; native host/model behavior and client approval remain the open Phase 25/31 acceptance gap.
