## Source details that determine the design

- `SitesController.getSites` calls `checkSakaiSession()` and `siteService.getUserSites()`, but ignores its `{userId}` path variable. It also returns notifications and tool links that the MCP contract does not need.
- `GradesController.gradeDataSupplierForSite` uses `getViewableAssignmentsForCurrentUser`, then switches between all gradable users and the current user based on grader permission. Its student branch checks `Assignment.getReleased()` before exposing a score. `GradingService` documents that non-graders with `viewOwnGrades` receive released items.
- `AnnouncementsController.getSiteAnnouncements` uses `siteService.getSite(siteId)` and an `isMessageViewable` filter. The live negative probe proves this is insufficient for an unrelated site. The new route must fail closed if `getSiteVisit` rejects the user.
- `AssignmentServiceImpl.allowGradeSubmission` checks `SECURE_GRADE_ASSIGNMENT_SUBMISSION`; `getGroupsAllowGradeAssignment` narrows the gradeable groups; `getSubmissions(assignment)` simply returns `assignment.getSubmissions()`. The controller must check assignment/site equality and filter submitters by allowed group/section scope before serialization.
- `BaseAnnouncementService`'s `AnnouncementChannel.addAnnouncementMessage` delegates to the permission-checked message add path. The normal UI uses `getAnnouncementChannel`, sets subject/body/header, then commits. The convenience overload `addAnnouncementMessage(subject, false, emptyAttachments, body)` commits through the same channel. V1 should set author from Sakai's current session and use plain posted announcements. A request transport failure after commit is ambiguous; the MCP service must not replay it automatically.
