# Phase 12 — fixed MCP V1 server (2026-09-27)

Status: **PASS for local service/protocol gate; cloud deployment NOT RUN**.

The pinned MCP Python 2.2 `MCPServer` provides one authenticated, stateless Streamable HTTP `/mcp` endpoint and protected-resource metadata. The five V1 tools are `list_my_courses`, `get_my_grades`, `get_course_announcements`, `get_course_submissions`, and `create_course_announcement`. The last is the sole write and is annotated non-idempotent. Each tool obtains the request's verified principal and uses the OBO-backed fixed Sakai client; no tool accepts a target user, token, base URL, or arbitrary destination. Bounded pagination reports when the Sakai route's source cap is reached. Sakai 25.2 was observed to serialize submission `Instant` values as floating-point epoch seconds, and the tool normalizes them to UTC ISO timestamps.

The catalog is static in V1: a student may see the instructor tool names. A trusted course-level capability feed does not yet exist for safely filtering catalog entries. Every invocation still requires a verified human token, and Sakai performs site and permission checks; manually invoking both privileged tools as a student returned `FORBIDDEN` with no read data or write. This limitation is visible to MCP clients and does not grant extra access.

The full local test suite passed **36/36**, with Ruff and mypy passing. Tests cover the exact tool catalog and annotations, output/pagination, missing principal, student privileged-call denial, no-bearer HTTP 401, authenticated protocol initialization/listing/call, and the Phase 9–11 auth/OBO/client checks. A separate local ASGI instance using fresh synthetic Entra tokens, certificate-backed OBO, and the public Sakai dev endpoint passed **10/10**: protocol initialization, five-tool listing, student course isolation/own grades/announcements, student privileged denials, instructor submissions, one permitted announcement creation, and student visibility of that creation. The local Python resolver needed a process-only mapping for the previously verified dev VM public address; the request retained the original HTTPS hostname, SNI, and certificate check. No cloud MCP deployment is claimed here.

The acceptance run created one additional synthetic announcement as durable Sakai test data. No token, credential, private key, user/site/assignment identifier, grade, submission, announcement text, or raw URL log is retained in this report.
