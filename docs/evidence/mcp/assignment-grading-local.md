# Assignment grading: local implementation evidence

Superseded architecture: this report records the historical importer implementation. The [MCP-only migration](../../SAKAI_GRADING_MCP_RESOURCES.md) removes that client and records new checks in [resource migration evidence](assignment-grading-resources-local.md).
Date: 13 October 2026. Scope: user-authorized implementation following the [9 October research/design](../../SAKAI_ASSIGNMENT_GRADING.md). **Historical local checkpoint: disabled by default, undeployed, no live grading acceptance at that point.** No Azure/runtime configuration or academic record was changed during this checkpoint. The later user-authorized deployment is recorded in [release evidence](assignment-grading-release.md). The pre-existing phase-25 and phase-31 evidence edits are unrelated and preserved.

## Implemented behavior

- Nine tools are independently gated by Python `ASSIGNMENT_GRADING_ENABLED=false` and Sakai `mcp.assignment.grading.enabled=false`. Default V1 remains five tools; setup adds its independent three. Catalog tests cover 5/8/14/17 combinations. The authenticated artifact route exists only with the grading gate.
- Native context, roster, detail and readback enforce delegated Sakai identity, site/assignment ownership, native grading permissions and effective scope. Roster pages include missing students, drafts and orphan records rather than silently truncating at the existing V1 limit. Changed metadata invalidates roster cursors. Anonymous identity reads are denied.
- Official writes initially support current submitted individual, site-wide point assignments with no Gradebook link or one verified Assignment-owned external point item. Each target must remain enrolled and eligible; linked Gradebook permissions are checked per student/item. Group/scoped writes, anonymous grading, group Gradebooks, non-point grades, numeric/internal links, rubric/peer/external submission integrations and historical attempts are deferred.
- Grade requests are capped at 60,000 JSON bytes as well as 100 rows; split larger approved sets into distinct bounded payloads. Exact decimal scores must fit the native scale and maximum. Save changes grade, graded-by/status and explicit feedback preserve/replace/clear only, preserving student content, private notes and overrides. Already released/returned rows cannot be saved. Return is separate: release-and-return sets the native flags/timestamp and copies score/plain-text comments to the owned external item without altering its released/counted flags.
- Assignment/submission database locks, source/config/grade revisions and native optimistic versioning protect against stale writes, including native UI/student writers. Projection runs under a second lock with the committed return revision; a resubmission before projection leaves partial state and prevents projection.
- An owner-only durable native journal checkpoints intent and each attempted row. Same-ID/same-hash replay returns the historical receipt without writing or notifying again; a different payload conflicts. Crashes, native errors or projection failures require independent readback and human reconciliation. No automatic rollback, blind retry, exactly-once notifications or automatic repair is claimed.
- Exports capture per-file bytes with SHA-256, generated paths and authoritative submission/user mappings. URL attachments are not fetched. Inline text is a UTF-8 HTML artifact, not plain MCQ text. Captures enforce 10 MiB/file, 100 MiB/export, 100 selections, 20 attachments/record and bounded inline text. Before/after source checks mark incomplete captures; omissions are explicit. ZIP/archive export is not implemented (`archive=null`).
- Status/download reauthorize current access, actor ownership and source attachment membership. Artifacts expire after 24 hours. Access to an expired export removes its generated byte files under the export lock, while retaining receipt metadata. Untouched expired exports need operator retention maintenance; automatic periodic cleanup is not configured. Do not enable without agreeing and verifying that maintenance policy.
- The MCP gateway streams authenticated bytes outside JSON/tool output, supports one HTTP byte range and closes the upstream stream. Range slices a full bounded native stream; it is not a native seek optimization. Descriptors contain no credentials or caller-selected URLs.
- The trusted CLI importer obtains institutional interactive OAuth with a registered public client in its own process. It stores no token cache or token output, verifies all hashes/sizes/paths, resumes by restarting individual files, preserves immutable raw bytes and records context, scoped roster and manifest in a private workspace outside Git. It never extracts archives or executes student code.
- The strict MCQ helper requires an explicit key/contract/policies, uses authoritative identity with approved filename checks, records separate normalization, exact scores, line evidence and config/manifest/script hashes. It emits `results/proposals.json`, `marks.csv`, `review-required.csv`; missing, unselected, incomplete, invalid or changed sources retain null scores. Non-null late penalties and other unsupported rules require another reviewed implementation.
- The repository [Skill](../../../skills/sakai-assignment-grading/SKILL.md) freezes a grading plan before bulk evaluation and requires separate approval of exact save and release-and-return payloads. It is not globally installed. Tool annotations or validation do not prove human approval.

## Source and local checks

Python source: `services/mcp/src/sakai_mcp/grading_{models,tools,artifacts,workspace}.py`, with independently gated server/ASGI/client integration. Native source: `apps/sakai/webapi/.../mcp/McpAssignmentGrading{Service,Controller}.java`, `McpGradingStore.java`, and narrow Assignment service/repository concurrency support. [Wire schemas](../../mcp/assignment-grading-contracts.json) remain self-contained for all nine tools.

Commands run from the repository (Python checks from `services/mcp`):

```sh
uv run ruff check src tests
uv run mypy src
uv run pytest -q
JAVA_HOME=/opt/homebrew/opt/openjdk@17 mvn -f apps/sakai/pom.xml -pl assignment/impl -am -Dtest='AssignmentGradingConcurrencyTest,AssignmentServiceTest' -Dsurefire.failIfNoSpecifiedTests=false test
JAVA_HOME=/opt/homebrew/opt/openjdk@17 mvn -f apps/sakai/pom.xml -pl webapi -am -Dtest='Mcp*Test' -Dmcp.grading.contractFixtures=/tmp/sakai-grading-contract-fixtures -Dsurefire.failIfNoSpecifiedTests=false test
./scripts/check-repo-context.sh
git diff --check
```

The optional Java fixture property emits synthetic responses outside Git; all nine are independently parsed by their Python output models to check the cross-language wire contract. The earlier webapi run included `LoginControllerTests` and passed 58 tests. The final focused run includes the additional Gradebook, mid-projection resubmission, withdrawn-student and physical-expiry cases. Real Hibernate tests use local HSQLDB; they do not establish production MySQL locking or UI conflict messaging.

Final results: **112 Python tests passed**, Ruff and mypy passed; **41 native Assignment tests and 63 MCP webapi tests passed** with zero failures/errors/skips, including 20 grading service cases and the real Hibernate stale-writer test. All nine native synthetic responses validated against the strict Python models. A mocked authenticated transport materialized the native synthetic artifact, verified its checksum and mode 0400, saved context/roster/manifest, then resumed without another byte download. This tests importer mechanics, not live OAuth or client compatibility. The skill-creator validator, repository-context check, schema/reference/link checks and `git diff --check` passed. Synthetic identities and content only; no production tokens, students, submissions, answer keys or grades are used.

## Required before deployment or enablement

Deployment/runtime changes require separate authorization. Follow [Sakai source/deployment boundaries](../../SAKAI_SOURCE.md), [runbook](../../Sakai_Deployment_Runbook.md), [pause/resume rules](../../PAUSE_AND_RESUME.md) and [identity/adapter requirements](../../mcp/sakai-adapter.md). A push does not deploy.

1. **Schema compatibility before deploying native source, regardless of flags.** `AssignmentSubmission` now has Hibernate `@Version` on `ASN_SUBMISSION.LOCK_VERSION`, a non-null `BIGINT DEFAULT 0`. Inspect the current schema and plan backup/maintenance. On MySQL, if the column is absent, the reviewed migration is:

   ```sql
   ALTER TABLE ASN_SUBMISSION ADD COLUMN LOCK_VERSION BIGINT NOT NULL DEFAULT 0;
   ```

   Do not run this blindly or rely on auto-DDL. Verify existing rows have zero/non-null versions and new native grade/student saves increment the column. Coordinate all native application nodes; old binaries do not participate in optimistic checks and cannot safely run concurrently with new ones. A rollback plan must keep the additive column/data and assess mixed-version writes. Test stale native UI writes and student resubmission conflict behavior on the intended MySQL/runtime configuration.

2. **Private durable storage.** Explicitly provision an absolute canonical non-symlink directory, mode 0700, owned by the Sakai runtime account, outside web-served paths/Git. Configure `mcp.assignment.grading.storage` only after choosing encryption, backup, retention/quota and operator cleanup policies. The store requires filesystem locks, atomic rename, file/directory fsync and persistent bytes across restart. Multiple MCP replicas proxy to this native storage; multiple Sakai nodes require a shared filesystem with verified cross-process locks and durability. Do not use ephemeral MCP container storage. The implementation fails closed on unavailable storage; it does not provision or chmod an arbitrary tree.

3. **Trusted client OAuth.** Register/grant the institution's public client, delegated MCP scope and interactive loopback callback under the existing approved identity process. Login JSON contains nonsecret tenant/client UUIDs and `mcp_origin=https://mcp.smartdigest.app`. Test on the actual host with the institution's consent policy. The importer cannot borrow a model-visible token or assume the host's OAuth cache is accessible.

4. **Live acceptance.** Establish Student denial and concrete TA/site/section/category/item authority, expired/revoked access, source attachment/hash semantics, native UI parity, Assignment-to-Gradebook values/visibility and approved feedback. Test restart, concurrent operation IDs, durable unknown intent, partial projection and required human reconciliation. Verify actual client materialization, interrupted downloads, approval UI and no sensitive logs. Never equate local mocks or wire parsing with these acceptance gates.

5. **Approval and maintenance policy.** Agree on exact TA save and separate return approval, proposal amendments, manual handling of uncertain rows, operation receipt retention, expired-file maintenance and privacy/AI processing rules. Keep both runtime gates off until storage/schema/client acceptance has passed. Semantic grading and student-code execution need their own reviewed pipelines; they are not part of the deterministic MCQ release.
